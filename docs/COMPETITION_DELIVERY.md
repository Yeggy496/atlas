# OptiDay · 六天提交准备建议

依据本次提供的赛题与作品要求整理。具体模板、文件大小、时长、提交时间以比赛正式通知为准。

## 推荐定位

优先选择赛题 2「AI＋软件创新」。作品强项是把自然语言理解、约束验证、严格求解和用户操作形成可用的软件闭环。个人计划、一个班的课表、小型实验团队是清晰的应用范围。

可采用介绍：

> OptiDay 将自然语言、表格与手工输入转为经过校验和用户确认的任务与约束，通过组合优化生成可检查的计划，并提供解释、冲突处理和少改动的重新安排。

创新点应写已经实现的统一模型、多场景适配、人工确认、独立校验、验证后的修复建议与重排对比。Google OR-Tools CP-SAT 和接入的大模型是成熟技术，须在材料中引用和说明，不写成团队自研算法。依赖与许可证见 `THIRD_PARTY.md`。

## 文档：建议 8 页左右

1. **问题与用户。** 一个大学生、一名班级排课人员、一个实验团队各有什么安排困难，说明目前服务的规模。
2. **使用流程。** 用自己的匿名任务截图说明：新建/导入 → AI 识别 → 检查确认 → 优化 → 查看/修复 → 备份。
3. **架构。** 输入、模型 Provider、JSON/Pydantic 校验、共享约束模型、CP-SAT、独立校验、日历与解释。明确 AI 调用的位置。
4. **统一模型与算法。** Activity、Resource、时间槽、硬约束、软偏好、加权目标、上一版安排的变更代价。足够解释即可，不堆术语。
5. **三种场景。** 每种展示同一套核心如何处理不同输入；排课展示班级＋教师＋候选教室，实验展示设备数量与前置关系。
6. **变化与冲突。** 临时会议前后对比；两实验同时占唯一设备，无解诊断、用户选择放宽、再次求解。记录真实状态和变更数。
7. **验证证据。** 系统测试、预置实例和真实试用分别列出。实验表附规模、环境、时限、状态、硬约束违反与原始结果。没有实际试用时写“可转化方案”，不能编造人数、满意度或效果。
8. **价值与边界。** 适用对象、部署方式、30 分钟精度、浏览器存储/备份、模型理解需审核、诊断与重排的局限及近期计划。

当前可引用的预置实验在 `docs/evidence-20261014/`：35 项个人任务、11 项课程、6 项实验，独立校验均为 0 硬约束违反。随机和简单贪心只是教学基线，尚不支持“超越先进算法”的结论；本轮未测大模型直接排程的效果。

## PPT：建议 10 页

1. 项目名称、产品定位、真实网站截图。
2. 用户任务与现有安排困难。
3. 输入、AI 理解、确认与求解闭环。
4. 共用模型、适配器及实际优化目标。
5. 个人计划与一次 AI 识别。
6. 一个班的课程、教师与教室。
7. 实验设备冲突与验证后的修复。
8. 临时会议重排的实际前后对比。
9. 实测结果、用户试用反馈（如果实际完成）、边界。
10. 当前产品入口、应用价值与后续计划。

每页一个主题，优先用截图、流程图和真实数据。文档解释细节，PPT 便于评委快速理解；两者的名称、功能和数据保持一致。

## 视频：建议 3–5 分钟

| 时间参考 | 操作 | 应证明什么 |
| --- | --- | --- |
| 0:00–0:20 | 网站全貌、简述适用用户 | 已有可操作的产品 |
| 0:20–1:15 | 个人需求 → AI 识别 → 修改/确认 → 生成 | AI 理解与严格求解分工，确认确实有效 |
| 1:15–1:55 | 新增临时会议，稳健重排，打开变化清单 | 实际变更可检查 |
| 1:55–2:35 | 导入课程，设置教师/班级/教室 | 多资源约束真实工作 |
| 2:35–3:20 | 两个实验占唯一设备的冲突，选择修复 | 无解处理闭环 |
| 3:20–3:45 | 下载备份，另一浏览器恢复，导出中文计划 | 能保存、接着编辑和交付结果 |
| 3:45–4:00 | 总结适用范围与当前边界 | 说明准确，不夸大成熟度 |

先打开网站完成唤醒，再录屏。长等待可以剪辑，但标明加速/省略等待，不把剪辑后的时长说成真实 API 或求解耗时。录制前准备匿名数据，逐项走通；不要录入密钥或打开服务器 Environment 页面。

## 匿名与原创性核对

所有提交材料、视频画面、文件名、文档属性和备注中，都不能出现所在学校名称及 Logo、指导教师信息。截图与视频只保留产品界面；检查浏览器标签、下载目录、桌面通知、页眉页脚及 PPT 备注。预置的“张老师”是调度资源示例，不能替换为真实指导教师信息。

提交前由团队审核原创性和真实性说明，清楚区分团队业务实现、开源依赖、模型 API、AI 辅助开发的范围及引用内容。团队应能解释代码与验证方法，按竞赛对辅助工具使用的要求申报；不要用 AI 生成未发生的实验、用户反馈或商业落地。
