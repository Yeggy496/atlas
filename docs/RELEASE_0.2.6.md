# OptiDay v0.2.6 · 清楚区分已有任务与本次需求

## 复现与范围

用户反馈只输入几门课，计划却出现未提到的课程。线上v0.2.5用两门课的匿名短句验证：空白个人计划与空白排课计划各识别出两项；在预置示例上识别时，个人计划原35项及排课预置的11项均被保留，包括没有提及的示例课程。这复现了一种明确成因，但不能断言朋友的具体情况只有这一种原因。

## 改动

- 现有活动或约束不为空时，识别前显示已有数量和部分名称，明确让用户选择保留并修改，或只使用本次描述。
- 后者向模型发送空活动和空约束，保留当前资源、场景和所在周。只有成功识别出活动才替换结果；失败、空结果、取消均保留原计划。成功替换支持撤销，并清除旧的重排基线。
- 本次识别默认显示活动列表。新增或改名活动的名称未直接出现在原文中时，提示用户复核；模型提示词也明确禁止自行补充课程。
- 超过4000字时提示分段及后续段应保留前段结果；场景提示、失败重试沿用所选识别范围。

名称匹配是辅助提示，可能将合理的简称或同义表达标记出来，也不能保证发现所有错误。模型仍可能误解需求，必须检查活动及约束再确认，不能用提示代替人工审核。

## 本地验证

后端192项通过、1项需要在线密钥的测试跳过。前端构建和同步通过；浏览器自动化覆盖10组新范围选择流程、5组场景提示流程、15组易用性流程及11组产品流程，包括手机布局、保留与替换、撤销、失败重试、空结果保护、备份与长文本分段。浏览器范围测试使用明确标注的模型替身，不代表真实模型准确率。部署后仍须用真实模型再次核对短输入和已有示例场景。
