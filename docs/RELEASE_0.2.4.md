# OptiDay v0.2.4 · 识别上下文补齐

## 用户反馈与调查

用户报告个人周计划仍出现识别失败。公开 v0.2.3 用原测试段落完成了空白、已有示例、不同所在周三种请求，均返回47项任务。进一步按当前输入框里没有“替换示例”前言的原文测试，在35项示例任务和已经识别过的47项任务上分别得到47项任务，耗时19.17秒和13.91秒。这些成功请求没有重现用户此次失败，不能据此判定其页面没有问题或将原因归咎于场景选择。

排查发现了一个可独立复现的上下文缺失：整体使用 `exclude_defaults=True` 会省略恰好等于Schema默认值的所在周，以及空约束数组。新增回归用例在修复前分别因缺少 `week_start` 和 `constraints` 失败。

## 改动

- 模型请求始终包含场景、名称、所在周、资源、活动、约束；仅压缩各条记录的默认属性。空数组明确表示当前没有内容。
- 提示词明确重复描述应更新对应任务，每周次数和总时长表示修改后的总量；保留无关任务，避免重复追加。
- 提示词明确“分两次”不等于“不同两天”；只有用户明确要求不同天时，才添加对应每日上限。
- 保留完整JSON校验、一次格式纠错、原总等待时限及人工审核，未放宽求解门槛。

后端186项测试通过、1项在线密钥测试跳过。两项新增用例覆盖默认日期和其他日期下的完整上下文传递，修复前均失败、修复后通过。本次没有改动前端交互和求解算法。

本版本尚需部署后用真实模型验收。提示词不能保证任意输入的语义准确率；模型识别与正式求解之间仍须复核。
