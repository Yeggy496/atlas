# OptiDay v0.2.3 · 长文本识别与场景提示

## 复现

同一段匿名个人周计划，在生产排程空白场景和个人周计划空白场景均收到 HTTP 422。两次耗时分别为 11.92 秒和 16.58 秒，返回的是模型输出校验失败；求解器尚未开始排程。仅提醒用户更换场景不足以处理这个问题。

## 修复

- 个人生活需求出现在其他场景时，后端先返回不收费的场景建议，界面允许取消、带着原文切换，或明确继续当前场景。切换保留已有任务，替换目标场景输入可撤销。
- 显式提供结构化输出预算：DeepSeek 默认 24576，OpenAI 默认 16384，可用对应 `*_MAX_TOKENS` 配置，受 1024–32768 上下界约束。
- 提示词明确半小时时间槽、全天窗口、整周截止时间、重复任务、不同项目的每日上限、已有资源引用；要求省略默认字段以减少冗余输出。
- 检查模型的完成状态；截断内容不能被当作完整方案接受。无效 JSON 或任务校验失败时，携带原输出及具体校验反馈重新生成一次，最多两次请求，共用原来的总超时预算。
- 网络、鉴权、限流、服务中断与内容过滤不按 JSON 格式问题自动重试。错误信息保留当前输入；日志不记录用户原文、模型输出或密钥。
- 模型不能偷偷改变当前场景和所在周。每次返回仍经过 Pydantic 与引用校验，必须由用户确认后才可进入 CP-SAT；没有跳过校验或丢弃坏任务来制造成功结果。

接口处理依据：[DeepSeek JSON 输出说明](https://api-docs.deepseek.com/guides/json_mode/)、[Chat Completions 参数与完成状态](https://api-docs.deepseek.com/api/create-chat-completion/)。JSON 模式本身不能代替业务约束校验。

## 验证范围

后端184项通过、1项跳过；原有79组浏览器回归与新增5组场景建议／取消／保留输入／撤销／审核门槛流程均通过。记录见 `evidence-20261027-parse/verification.json`。新浏览器脚本的模型成功响应使用明确标注的替身，只验证交互，不代表真实模型对长段需求的识别成功。真实长文本必须在部署后再验收，不能用离线规则或测试替身充当大模型结果。

复现用原文位于 `sample_data/weekly_planning.txt`。版本发布后，应切到个人周计划，用这段原文识别，检查每日睡眠和用餐、固定课程、作业截止时间、学习次数、报告前置关系以及可选活动，再确认求解；不能仅以返回 HTTP 200 判断所有意图都理解正确。

## 部署后真实验收

已在公开网站 v0.2.3 使用原段文字完成真实 DeepSeek 调用：一次请求，12.51秒，47任务、54约束；未确认请求被409拒绝，确认后CP-SAT在30秒内返回FEASIBLE，47项全部安排，独立验证0硬约束违反。

另对原文关键条件做了22项核对，包括七天睡眠、每日两餐、八项固定日程、两次高数作业及截止、Python和英语及跑步的次数与分日、报告先后与截止、周末家务、可选阅读及周六游戏，均符合本次生成的计划。单次成功不代表任意输入的准确率或时延保证。

复核中也发现模型额外增加了“高数作业每天最多一次”：原文仅要求分成两次。此额外限制并未使本次方案违反原文，但不应当作用户明确要求；确认前可删除。用户复核仍然是正式求解前的必要环节。
