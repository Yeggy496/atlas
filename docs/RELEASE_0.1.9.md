# v0.1.9 · 完整的个人工作流程

日期：2026-10-14。保留现有页面风格、五个场景及共享 CP-SAT 核心，重点完善个人、一个班和小型实验团队的使用体验。

## 本轮完成

- 新建自己的计划：清空当前活动和约束、保留可编辑资源，不再只能从预置任务逐个删除。恢复预置、新建和恢复备份都有确认，并可撤销内容修改。
- 周日期选择：选择任意日期后使用所在周的周一，后端校验真实日期和星期，避免日期与日历列错位。
- 资源管理：修改教师、班级、场地、设备的名称、类型、并发数量、座位和场地类型；支持新增、搜索及删除未被引用的资源。
- 活动录入：支持多项占用资源及数量、候选场地、座位和类型要求、允许日期与时间范围。原有复杂活动字段在编辑后保留。
- 工作空间备份与恢复：可备份未完成输入、任务、约束和设置，在另一浏览器恢复。导入 JSON 先经过前后端校验，再强制重新确认与求解；不直接接受文件中的求解状态。
- 数据保护：求解历史只保存在当前浏览器，保留最近 12 条。公共部署默认不保存或展示共享访客历史，已有服务器记录也不会返回。工作空间和历史的存储错误分别提示。
- 重排变更：依据两次真实安排显示保留、调整、新增和移出；旧活动与资源名称随上一版数据保存。删除最后一项同类活动会清理悬空约束，删除工序后重新编号。
- 操作反馈：增加步骤提示、实际等待秒数、初次唤醒说明、真实连接状态及空白计划指引，修正必做任务时长的统计标签。
- 导出：中文 PDF、多页表头和长文本换行；午夜结束显示 24:00。Excel 用户文本不会被识别为公式。

后端分组执行：核心 89 项、导出及 API 回归 20 项、基准测试 5 项，共 114 项通过。1 项本地真实模型测试因未配置本地密钥跳过；这不代表线上模型未接入。

浏览器脚本实际访问 FastAPI 和 CP-SAT，没有替换求解结果：

- `check_browser_storage.py`：10 项数据恢复、跨标签页、损坏数据及存储失败检查通过。
- `check_ui_regressions.py`：9 项表单、权重、稳定性、日历和手机检查通过。
- `check_product_workflows.py`：覆盖新建、撤销、跨场景恢复、备份、历史隔离、资源管理和手机操作。
- `check_resource_workflows.py`：覆盖多资源课程、设备数量、场地分配、保留原字段及资源删除保护。

可复现的三个预置场景数据见 [实验原始记录](evidence-20261014/benchmark_results.json) 和 [结果表](evidence-20261014/benchmark_results.md)。在本机 4 秒求解预算下，35 项个人任务和 11 项课程取得 FEASIBLE，6 项实验取得 OPTIMAL，独立校验均为 0 条硬约束违反。这是预置实例验证，不是真实用户试点或规模泛化结论。

## 实际能力边界

AI 用于自然语言转结构化模型及解释润色，正式调度始终由 CP-SAT 完成。使用成熟模型和求解器，不宣称自研底层模型。诊断通过有限次数的约束放宽重新求解验证，不保证找到全局最小冲突核心；稳定性是优化目标，不保证每次变化都是数学最小。

时间精度仍为 30 分钟。无账号或自动跨电脑同步；需要下载备份再恢复。任务数据会提交服务器求解，AI 识别和解释也会调用配置的模型服务。免费 Render 服务仍可能在闲置后需要唤醒，购买域名不会改变这个行为。

默认关闭服务器历史。`OPTIDAY_SERVER_HISTORY=true` 只用于可信的单人本机服务，公共服务应保持关闭。

## 接力修改

最新源码以 GitHub main 为准，环境变量与密钥仍由接手人或部署环境单独配置。修改前端后必须重建并同步 `frontend/dist` 与 `backend/app/webapp`，再推送并部署同一提交。录制或展示前确认 `/api/health` 版本和实际页面一致。
