# v0.1.8 · 交互细节修复

日期：2026-10-13。保留现有布局、统一约束模型、AI 接口和求解器，不引入运行依赖。

- 切换优化模式时携带上一版安排。稳健模式现在能实际使用最小扰动目标，而不是在切换时丢掉上一版安排。
- 重新求解时显示后端实际计算的原活动调整数，方便查看当前任务中已有活动的变化；新增和已删除任务不计入该指标。
- 每个权重滑块的范围包含该维度的真实预设值；最小扰动权重 1000 不再被控件的上限 120 截断。
- 自定义权重区分“待应用”和“当前计划已应用”；未确认任务与约束时禁用应用按钮，调整模式的提示与实际行为保持一致。
- 活动与约束保存失败时，错误显示在编辑弹窗内；禁止只包含空格的名称，保存中阻止重复提交。控件名称明确，约束分类使用中文。
- 约束类型切换同步有效的作用对象、固定日期及截止时间，避免表单显示的选项与提交的实际值不一致。
- 已有约束的中午等精确截止时刻保留并正确显示，不再因日期末选项不足而看起来像另一个时间。
- 日历图例来自当前任务类别，会议和工序颜色与事件一致；全天视图补充睡眠图例。
- 睡眠摘要保留半小时精度；不同睡眠时长显示实际范围，不再把 7.5 小时显示为 8 小时，或将不同安排都描述成同一时长。
- 提示框使用保持水平居中的动画，避免手机上的入场动画短暂将内容和关闭按钮推到屏幕外。

## 验证

- TypeScript 检查和 Vite 生产构建通过。
- `scripts/check_ui_regressions.py` 在真实 API 和 Chromium 中验证稳健重排、滑块数值、权重应用状态、草稿确认、服务器校验失败后的修正、类型切换、会议/工序图例及不同睡眠时长。未改变任务时切换稳健模式，本地实际变动数为 0。
- `scripts/check_browser_storage.py` 的十类保存与恢复检查通过；恢复草稿后实际求解 36 项活动，硬约束违反为 0。
- 无浏览器页面异常；测试中预期的 HTTP 422 校验失败能够显示并修正。390px 手机页面无整体横向溢出。

旧版本的浏览器保存格式保持兼容。既有服务端共享历史、免费托管和其他能力边界仍按前面的说明，不代表所有输入都已验证。
